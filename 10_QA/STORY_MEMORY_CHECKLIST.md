# Story Memory QA — Mystery & Foreshadowing Gate

Use this checklist whenever a chapter or arc plants, reinforces, connects, reveals, pays off, retires, or materially depends on a mystery/foreshadowing thread.

Authority: `01_CANON/WORLD_BIBLE.md` remains highest. The ledgers under `01_CANON/STORY_MEMORY/` are derivative continuity memory and cannot create new canon by themselves.

## Before drafting

- [ ] Relevant `MY-####` mystery records were loaded.
- [ ] Relevant `FS-####` foreshadowing records were loaded.
- [ ] The current reader knowledge state is understood.
- [ ] Character/faction knowledge is limited to valid discovery paths.
- [ ] Any `UNRESOLVED` truth remains unresolved; no final answer was invented for convenience.
- [ ] Any `PARTIALLY_LOCKED` future event preserves its locked and undefined portions exactly.
- [ ] Forbidden reveal/payoff guards are respected.

## During planning/drafting

- [ ] Every new intentional long-term seed receives or references a stable `FS-####` ID before later chapters depend on it.
- [ ] Every new major unresolved reader question that must survive across arcs receives or references a stable `MY-####` ID before later chapters depend on it.
- [ ] A planned seed is not marked `PLANTED` until approved prose actually contains it.
- [ ] A clue narrows or deepens a mystery without accidentally solving more than intended.
- [ ] Red herrings are marked as red herrings/false assumptions only after canon establishes them as such.
- [ ] The chapter does not use author-only truth as character knowledge.
- [ ] The chapter does not produce a payoff whose required setup has not been planted/reinforced.

## After canonization

- [ ] Exact chapter references were added to every affected ledger entry.
- [ ] Reader knowledge was updated to match what the prose actually revealed.
- [ ] Relevant character/faction knowledge was updated where needed.
- [ ] `PLANNED / PLANTED / REINFORCED / PAYOFF_DUE / PAID_OFF` status matches the actual prose state.
- [ ] `OPEN / PARTIALLY_REVEALED / REVEAL_DUE / RESOLVED` mystery status matches the actual prose state.
- [ ] Reveal/payoff consequences are recorded, not just the answer itself.
- [ ] Bidirectional links between `MY-####` and `FS-####` records still agree.
- [ ] Resolved/paid-off records are moved to the proper archive only after immediate consequences and links are complete.
- [ ] No retired/resolved ID is reused.
- [ ] The Story Studio safe checkpoint/state delta includes the mystery/foreshadowing change when relevant.

## Long-series health check

At each arc close:

- [ ] No active mystery has been silently forgotten for multiple arcs without an intentional reason.
- [ ] No major foreshadowing thread has exceeded an established payoff window.
- [ ] Repeated reminders vary naturally rather than restating the same clue.
- [ ] Old clues remain compatible with the planned truth.
- [ ] A reveal recontextualizes earlier material where appropriate instead of appearing from nowhere.
- [ ] Too many mysteries are not resolved simultaneously without creating new forward tension.
- [ ] Active ledger files remain compact; completed records are archived.
